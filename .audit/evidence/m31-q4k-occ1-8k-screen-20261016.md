Date: 2026-10-16 (UTC)

## Result

One 8,192-token Qwen3.8-27B Q4_K_M prefill sample per build on Machinist
GPU0 (`0000:04:00.0`) measured:

| Build | Occupancy-one option | Wall time | Prompt rate | Junction start → peak |
| --- | --- | ---: | ---: | ---: |
| Control | Off | 33.470 s | 244.76 tok/s | 27 C → 83 C |
| Candidate | On | 45.686 s | 179.31 tok/s | 40 C → 82 C |

The candidate was 12.216 s (36.5%) slower in this screen. Both `llama-bench`
processes exited 0 and returned one JSON result for 8,192 prompt tokens and
zero generation tokens. This is a directional screen, not a decision-grade
performance comparison: it has one sample per build, and their starting
temperatures differed by 13 C.

The default temperature trace has an unexplained sample discontinuity from
83 C to 60 C one second after its peak. The independent in-run check observed
80 C while the candidate was active. The candidate trace peaked at 82 C. Both
runs completed without reaching the runner's 84 C stop threshold, but the
temperature discontinuity should be accounted for before repeating sustained
work.

## Interpretation

The present evidence points against occupancy one, but does not isolate its
effect from the different start temperatures or establish a repeated median.
Keep the default unchanged. If a safely matched repeat confirms a substantial
regression, remove the occupancy-one option from the candidate branch rather
than spending more time tuning this setting.
