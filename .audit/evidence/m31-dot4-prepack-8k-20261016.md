# Q8 dot4 prepack: 8K full-model screen

This screen compares the unchanged/default attention dispatch with the opt-in
prepacked-Q Q8 dot4 path on the same Machinist MI50 (GPU2, BDF
`0000:88:00.0`). Both runs used the same 8,192-token Qwen3.8-27B Q4_K_M
prompt, Q8 K/V, Flash Attention, 99 GPU layers, `-b 2048 -ub 1024`, and one
sample without warmup. The candidate run set
`GGML_CUDA_FA_Q8_DOT4_PREPACK=1`.

| Route | Wall time | Prompt throughput | Start junction |
| --- | ---: | ---: | ---: |
| Default | 33.936 s | 241.398 tok/s | 31 C |
| Q8 dot4 prepack | 41.449 s | 197.639 tok/s | 36 C |

The candidate took 22.1% longer in this one-sample screen. It is a negative
directional result, not a repeated performance qualification. The candidate
reached 50 C junction after the run; the default reached 51 C. The caps were
225 W and 300 W, and the sustained-prefill guard now requires both cards at
180 W or below. Do not use this screen to qualify 64K operation or thermal
margin.

Both benchmark JSON records reported build commit `unknown`, and per-run
`libggml-hip.so` hashes were not captured. The run metadata does include the
same source base (`e57aad81ae1fc5c8fa8d71a680a025be6e64b992`), model SHA
`7e78da5d7e3ae28d178121f58646953305f3e5bd3cb46f4a75584e8b6c6fe169`, and
identical `llama-bench` frontend hashes. Treat this result as evidence that
the current path is not promising at 8K, and verify backend-library identity
before using it for a final comparative claim.

The accompanying CLI attempt did not verify generated text: its prompt
tokenized to 5,807 tokens with a 4,096-token context, so both runs rejected the
request before generation. No correctness conclusion is drawn from those
logs.

Raw benchmark logs and temperature traces are in this directory. The CLI
failure logs and prompt hash are in `m31-fork-cli-correctness-20261016/`.
