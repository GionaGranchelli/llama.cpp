## Exact-build recheck and full-model screen

The failures above came from the earlier smoke invocation and are superseded
by the following rerun against the final synchronized source and rebuilt
`test-backend-ops` binary. The source remained at local fork commit
`e57aad81ae1fc5c8fa8d71a680a025be6e64b992` with the uncommitted candidate
changes listed above. The `llama-bench` executable SHA-256 is
`540df0e549454caf6b4b199520fb33c3ec6b04f5e41b3689b7e2c52733c4659d`.

- The exact `FLASH_ATTN_EXT` support filter selected the intended
  `hsk=256, GQA=6, kv=512, nb=4, Q8_0/Q8_0` case and reported `SUPPORTED`.
- With dot4 disabled, that case passed **1/1** on ROCm0.
- With `GGML_CUDA_FA_Q8_DOT4=1`, that case passed **1/1** against the CPU
  reference. The complete Q8/Q8 `FLASH_ATTN_EXT` filter passed **370/370**.
- A verbose 512-token full-model run printed the dot4 selection log. GGUF
  metadata confirms `qwen35`, 24 query heads, 4 KV heads, and 256-wide key
  heads. The 8K benchmark itself used llama-bench's default quiet logger, so
  it did not emit per-operation route logs.
- One matched 8K sample on GPU2, BDF `0000:88:00.0`, used the same binary,
  image, model, batch/cache settings, and default dispatch except for the
  opt-in flag. Default: **33.879 s / 241.799 prompt tok/s**, junction
  **31-78 C**. Dot4: **40.053 s / 204.531 prompt tok/s**, junction
  **36-77 C**. This is a one-sample screen, not a qualified timing range; it
  indicates a **18.2% wall-time regression** and **15.4% lower throughput**.
- Both full-model samples exited successfully. No numerical/logit comparison
  was performed by llama-bench. Keep dot4 opt-in and do not claim full-model
  correctness or a speedup.

Raw logs, exit codes, benchmark JSONL, and per-second temperature traces are

## Interleaved 8K repeat screen

A second default/dot4 pair was run on GPU2 using the same binary SHA,
`540df0e549454caf6b4b199520fb33c3ec6b04f5e41b3689b7e2c52733c4659d`, model,
container image, and benchmark settings. The binary still reports
`build_commit=unknown`; these results are identified by binary hash, not source

| Order | Path | Time | Prompt throughput | Junction during run |
| --- | --- | ---: | ---: | ---: |
| 1 | Default, earlier sample | 33.879 s | 241.799 tok/s | 31-78 C |
| 2 | Dot4, earlier sample | 40.053 s | 204.531 tok/s | 36-77 C |
| 3 | Default | 33.884 s | 241.769 tok/s | 32-79 C |
| 4 | Dot4 | 40.099 s | 204.296 tok/s | 33-77 C |

| 6 | Dot4 | 40.064 s | 204.474 tok/s | 38-80 C |

Both paths have three samples. The medians are 33.884 s for default and
40.064 s for dot4, making dot4 18.2% slower by the ratio of medians. Each
adjacent pair also shows a slowdown: 18.2%, 18.3%, and 18.0%. This is a
repeatable diagnostic regression on this 8K setup, not a broad performance
qualification. The last two runs reached the 80 C warning (81 C for default,
80 C for dot4) but completed below the 84 C stop threshold. Raw logs, metadata,
and temperature traces for the repeat runs are in `gpu2-repeats/` and
`gpu2-repeat-screen.tar.gz`.
